## 大疆无人机场景道具

[drone.ts](drone.ts) 独立加载 `public/models/drone/djiair.glb`，由赛车宿主传入模型 URL、
米制宽度与悬停偏移（1 Three.js 单位 = 1 米）。`update(dt, { position, heading })` 接收米制世界坐标和弧度朝向，
不依赖具体车型或地图，也不继承车辆 GLB 的缩放。按原包围盒整体等比归一化，将原模型 -Z 机头转为 +Z。
当前赛车配置为展开宽约 0.42 米，右侧 2.7 米、前方 3.2 米、上方 2.8 米，并叠加轻微悬停起伏。
这是随车展示动画，不是无人机飞行动力学或避障系统；原 GLB 没有独立桨叶节点，暂不旋转螺旋桨。

`load()` 并发调用复用加载任务，失败可重试；`setEnabled()` 控制可见性，`state()` 提供加载状态，
`dispose()` 释放几何、材质与贴图。模型异步加载，不阻塞车辆；`?drone=0` 跳过初始加载。
使用已有环境光、阴影和反射，不创建额外光源或反射相机。法线图离线缩至 2048²，其他资源保持不变。

设置弹窗提供显示开关和近景查看；`window.__RACE__.drone()` 返回诊断信息。
自由视角可缩放到距观察中心 5 厘米；近裁剪面随观察距离自动缩小，支持检查机身细节。
MCP 通过 `decoration.drone` 查询坐标或定位相机。验证：`node .qa/drone-check.mjs`。
资源署名见 [ATTRIBUTION.md](../../public/models/drone/ATTRIBUTION.md)。

## 布置规则

[bridge.ts](../water-sky/bridge.ts) 的 `plantedMedian: true` 创建低矮种植槽，并加载 [medianTrees.ts](medianTrees.ts) 与 [medianLamps.ts](medianLamps.ts)。桥、环线启用；无尽赛道未启用。全部位置按物理桥中心线计算，不能使用环线的往返行车中心线。

| 对象 | 资源与处理                                                                                  | 布置                                           |
| ---- | ------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 椴树 | `public/models/trees/linden/Linden.fbx`；Z-up 转 Y-up，烘焙完整节点变换，保留树皮／枝叶贴图 | 约 5.2 米高、14 米间距，带确定性角度和大小差异 |
| 路灯 | `public/models/street_lamp.glb`；Y-up、原灯臂朝 -X，以灯杆底部为原点归一化                  | 约 8 米高、28 米一组，每组两根分别朝向左右车道 |

资源从用户提供的椴树压缩包和路灯 GLB 复制到项目；运行时不访问 `D:\learnProject`。树木使用 `InstancedMesh`，每批最多 6 棵；路灯每批最多 4 组，每个原始网格分别实例化。批次有独立包围体，减少远处整排模型无法剔除的问题。

灯位与树位错开；桥塔附近按配置排除，两端缺口继承 `medianGapAtEnds`，避免挡住环线掉头。数量随长度、间距和排除区变化，不应写死。

## 昼夜照明技术

灯罩发光与路面受光分别实现：

1. 仅将 GLB 材质名为 `light` 的实际灯罩改为不透明暖白发光材质，避免原资源低透明度导致看起来不亮；灯杆保留原材质。
2. 创建固定 **8 个 SpotLight**，更新为相机附近最多 4 组灯位，照向两侧路面。远处灯罩仍发光，但不各自占用实时光源。
3. 根据相机距离平滑降低强度；白天灯池 intensity 为 0，保持光源数量不变，避免昼夜切换触发所有材质重新编译光源变体。
4. 夜晚发光进入赛车现有 Bloom；黄昏不额外开启全场景 Bloom。

| 参数                           | 白天 |   黄昏 |   夜晚 |
| ------------------------------ | ---: | -----: | -----: |
| 灯罩 `emissiveIntensity`       |    0 |      5 |     14 |
| 聚光灯 intensity（淡出前，约） |    0 | 236.72 | 473.45 |

共用参数：暖白色 `0xffdda6`、距离上限 `height * 3.3`（当前约 26.4 米）、半锥角 `0.85 rad`、penumbra `0.8`、decay `2`。统一米制后，原聚光灯 intensity 按 `4.36²` 换算，保持原有距离衰减和路面亮度；曝光与发光材质不变。

聚光灯不生成单独阴影贴图，灯杆投射太阳阴影。因此路面照明是实时光源，但局部遮挡不具备每盏灯独立的投影阴影。

## 宿主接口与诊断

`createMedianLamps(options)` 返回 `MedianLampGroup`：

```ts
lamps.setTimeOfDay('dusk')
lamps.updateLighting(camera.position)
```

- `setTimeOfDay('day' | 'dusk' | 'night')`：切换灯罩状态，支持在异步载入完成前设置。
- `updateLighting(viewerWorldPosition)`：接收相机世界坐标，在反射与主渲染前调用；不要只放在车辆运动逻辑中，否则暂停／拖动相机时不更新。
- `group.userData.lamps`：加载状态、组数、数量、时段、亮灯状态、活动光源数及错误。
- 赛车诊断：`window.__RACE__.info().medianLamps`；树木诊断：`window.__RACE__.medianTrees()`。

这些装饰挂在地图上，不加入车辆的 GLB 部件树。替换路灯资产时，需重新检查灯罩材质名、源模型前向、杆底位置和完整缩放，现有适配针对当前资源。

## 中国结挂件

`lampKnots.ts` 为每根路灯增加一个中国结与短支架。挂点为灯高的 74%，
挂件约 2 米高，顶部挂环对齐支架端点，两侧挂件宽面朝向各自来车方向。
它使用实例化批次，共享几何与材质，随路灯站点自动避开桥塔和掉头口。

挂件现在有三档精度：近景约 6.14 万面、中景约 7600 面、远景约 2300 面，
分别在约 10 米、44 米处切换，约 152 米外剔除（边界有 8% 滞回，防止反复切换）。
三个精度池与支架共四个批次；所有精度共用相同挂点，不能按各自包围盒重新居中。
只有近景挂件投射／接收太阳阴影。`updateLighting()` 在白天也会更新挂件精度，
所以暂停、拖动相机和夜晚切换时同样生效。

用户提供的 `dreaming_knot_chinese_knot-.glb` 含三组挂件。离线工具
`tools/prepare-chinese-knot.mjs` 抽取 `knot:knot_2`，保留上部 8 个网格及其顶点颜色，
替换原来 3 个卷曲流苏网格及红色横结下向外翘的金色连接绳／绿色珠子。
近景上部约 3.59 万面，加上程序化连接绳、珠子和细丝后约 6.14 万面，
生成约 3.5 MB 的 `public/models/decorations/chinese-knot.glb`。
不修改原文件，浏览器无需加载完整 53 MB 资源。
减面只在离线运行，运行时不需要 Meshopt 解码器。

挂件采用粗糙丝线材质，并对近距离灯光的反射亮度做局部压缩，避免被夜间 Bloom
处理成发光灯串。来源、作者与 CC BY 4.0 署名见
[ATTRIBUTION.md](../../public/models/decorations/ATTRIBUTION.md)。

验证命令：`node .qa/lamp-knots-check.mjs`，覆盖桥／环线数量、载入错误以及日夜近景截图。
`node .qa/knot-lod-check.mjs` 检查精度切换、挂点一致性、剔除及远景阴影关闭。
`node .qa/scenery-performance.mjs` 比较固定旋转视角下的整帧绘制量；GPU 同步仅在诊断接口执行。

流苏采用结构重建：离线 `tools/knot-tassels.mjs` 从上部模型的四个绿色悬挂珠测量根点，
以独立管状细丝生成四束垂直流苏，增加收口与细小的长度差异。近／中／远每束分别为
36／12／5 根细丝，根点和整体长度保持一致。颜色仅用于纤维着色，不再用颜色划分悬挂根点。
红色横结及以上原有造型保留，近景材质增加轻微丝绸光泽。
红色横结以下另建四组金色双绳和小编结，绿色珠子与流苏垂直位于其下，
消除原连接绳向前翘起的静止造型。

运行时 `knotMotion.ts` 在顶点 Shader 中加入小幅摆动，顶部挂点固定，
主体小于 1 度摇摆，金色连接绳以红色横结下的根点为约束连续弯曲，
珠子和流苏继承连接绳末端的偏移与切线。每束流苏另以自己的根点为约束，弯曲位移沿长度的平方增长，
使根部位置和切线保持稳定，末端柔和摆动；近景阴影使用同一个变形函数。
静止相机下只更新统一时间值，不更新实例矩阵，也不增加绘制调用。
这不是完整绳索／布料物理，没有自碰撞。`node .qa/knot-motion-check.mjs`
检查四个独立悬挂根点、纤维垂直分布、连接绳与珠子区域的渲染运动、固定时间可复现及实例缓冲未逐帧上传。

## 场景检查命令

保持 Vite 在 5173 端口运行，在 `preview` 执行：

```powershell
node .qa/median-lamps-check.mjs
node .qa/median-lamp-lighting-check.mjs
```

前者检查双向摆放、数量与落地位置；后者检查白天／黄昏／夜晚循环、直接时段 URL 和异步加载，并在固定曝光下隐藏灯模型，对比道路是否真的被光源照亮。
